# Architecture

PetForge is a local-first monorepo. The browser creates and edits pets through the FastAPI REST API. The API validates images, stores source and processed files behind a storage interface, persists configuration in SQLite, and exports a portable package. Godot reads only that package and runs independently from Web/API.

```text
Next.js editor ── REST/JSON + multipart ── FastAPI ── SQLite
                                           ├── StorageProvider (local now; object storage later)
                                           ├── BackgroundRemovalProvider (edge matte now; SAM2 later)
                                           └── AnimationGenerationProvider (explicit mock)

Pet package (pet.json + character.png) ── Godot 4 runtime
```

The package schema is versioned and shared. API schemas validate inbound and outbound data; the Godot loader checks the version and required fields before constructing runtime settings. The runtime owns its state machine, animation-player fallback, screen bounds and behavior scheduler. It does not depend on a live API after launch.

## Trust boundaries

- Uploads are limited by size, extension, MIME and decoded image format; file names are generated by the server.
- Pet IDs are generated by the server and path resolution remains inside the pet storage root.
- Desktop launch is a local process action and requires an explicitly configured Godot executable.
- Background removal declares its provider and limitations. The mock animation provider never claims to create media.

## Future character consistency

Reference Image → Character Encoder → Motion/Pose Condition → Image-to-Video → Background Removal → Frame Extraction → Sprite/Animated WebP → Desktop Runtime. V0.1 only defines provider and animation-player seams; it does not generate video or bind Live2D.
